The bootstrap log line ALSO prints this tenant's agent ingest token —
capture it from the same `kubectl logs` command right after first
install, since it's only ever shown that one time. Put it in
CHIDRIXX_AUTH_TOKEN on every kharcha agent that ships to this tenant.

To provision an additional tenant (real data isolation, not just a second
user), or an additional user (e.g. a read-only viewer) on an existing
tenant, exec into the running pod:

  kubectl exec -it -n {{ .Release.Namespace }} deploy/{{ include "chidrixx-controlplane.fullname" . }} -- \
    /app/controlplane create-tenant --db /data/controlplane.db \
      --name <name> --admin-user <user> --admin-password <password>

  kubectl exec -it -n {{ .Release.Namespace }} deploy/{{ include "chidrixx-controlplane.fullname" . }} -- \
    /app/controlplane create-user --db /data/controlplane.db \
      --tenant-id <id> --username <user> --password <password> --role viewer
